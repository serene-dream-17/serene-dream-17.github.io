01

应用安全Application Security

应用安全的目标不是「没有漏洞」，而是把攻击面、信任边界与失败方式讲清楚。

  • 注入：SQL / 命令 / 模板注入的根因是「把数据当代码」，参数化查询与白名单是默认解。
  • XSS：输出编码要按上下文（HTML / 属性 / URL / JS）分别处理，CSP 是第二道防线。
  • CSRF / SSRF：校验来源与目标地址，服务端不要信任客户端传来的 URL。
  • 反序列化：只反序列化可信结构，优先使用 JSON 等无执行语义的格式。
  • 访问控制：每个请求都要在服务端重新判定权限，不能依赖前端隐藏。

代表工具：Helmet · Semgrep · Bandit

02

身份与访问Identity & Access

认证回答「你是谁」，授权回答「你能做什么」；两者要有清晰的边界。

  • OAuth2 负责授权委托，OIDC 在其上补充身份层；不要把 OAuth2 当成认证协议。
  • SAML 仍常见于企业 SSO；新系统优先 OIDC。
  • RBAC 适合角色稳定的系统，ABAC / 策略引擎适合细粒度与动态条件。
  • 会话令牌要短生命周期、可吊销，并绑定设备或来源风险。
  • 多因素认证对管理后台、支付与高危操作应默认开启。

代表工具：Spring Security · Keycloak · Open Policy Agent

03

密码学与密钥管理Cryptography

不要自己发明密码学；选成熟库、用 AEAD、把密钥生命周期当成一等公民。

  • 对称加密优先 AES-GCM / ChaCha20-Poly1305 等 AEAD 模式。
  • 非对称加密用于密钥交换与签名，不用于加密大块数据。
  • 哈希用于完整性，口令存储用 Argon2 / scrypt / bcrypt 等慢哈希。
  • 密钥轮换、吊销与备份要和业务发布流程一起设计。
  • 随机数必须来自操作系统 CSPRNG，禁止使用时间戳或语言默认随机。

代表工具：OpenSSL · libsodium · rustls · GnuTLS · age

04

安全编码规范Secure Coding

安全编码把「默认安全」写进团队习惯，而不是依赖上线前的最后一次扫描。

  • 输入校验：长度、类型、范围、编码四件事在边界处一次做完。
  • 输出编码：模板引擎默认转义，手写拼接必须走统一的编码函数。
  • 最小权限：数据库账号、容器权限、云 IAM 都按最小集合授予。
  • 密钥管理：密钥不落代码库、不落日志，使用 KMS / Vault 并定期轮换。
  • 错误处理：对外返回通用错误，对内保留可审计的上下文。
05

供应链与依赖安全Supply Chain

现代应用的代码大部分来自依赖；供应链安全的核心是「知道用了什么、能否追溯」。

  • 生成 SBOM，记录直接与传递依赖的版本、许可证与来源。
  • 锁定依赖版本与校验和，构建过程可复现。
  • 镜像与制品签名，部署前验证签名与来源。
  • 持续扫描已知漏洞，但要以可达性与实际暴露面排序。
  • 内部包仓库与代理缓存降低上游被投毒的风险。

代表工具：Trivy

06

渗透测试 / 红队Penetration Testing

渗透测试用授权的攻击视角验证防御是否真的生效；范围、规则与报告比工具更重要。

  • 授权与范围：书面授权、测试窗口、禁止事项与应急联系人，先于任何扫描。
  • 侦察：资产、子域、端口与服务优先；被动情报先行，避免打草惊蛇。
  • 利用：以验证影响为目标，拿到证据即停，不在生产环境做破坏性利用。
  • 提权与横向：从单点失陷到域控或云控制面是最常见的目标链，检测覆盖同样重要。
  • 报告：复现步骤、影响、证据与修复建议缺一不可，修复后要复测闭环。

代表工具：Nuclei · OWASP ZAP · Metasploit Framework · Burp Suite · sqlmap · BloodHound · hashcat

07

网络与流量安全Network Security

网络层是攻防共同的地基：先看清流量，才能判断什么是异常。

  • 抓包与协议分析：先建立基线，再看偏离；加密流量重点看元数据与指纹。
  • 分段与边界：VLAN、ACL 与零信任不是配置清单，要验证实际可达性。
  • 检测：IDS/IPS 规则、NetFlow 与 DNS 日志组合，比单点告警可靠。
  • 无线与近场：WPA2/3、EAP、蓝牙与 RFID 的暴露面常被忽略。
  • 中间人与欺骗：ARP / DNS / LLMNR 类欺骗在扁平内网依然有效，需主机侧防护配合。

代表工具：Wireshark · Scapy · Suricata · Aircrack-ng

08

逆向 / 二进制分析Reverse Engineering

逆向回答「这段二进制到底做了什么」，是漏洞分析、恶意样本与兼容性工作的共同基础。

  • 静态分析：反汇编、反编译与符号恢复；先看字符串、导入表与控制流。
  • 动态分析：调试器、沙箱与 API 监控；注意反调试与环境检测。
  • 插桩：Frida 一类工具可在不改包的情况下观测函数入参与返回值。
  • 固件与嵌入式：提取文件系统、识别架构与加载地址是第一步。
  • 法律边界：只分析自有、授权或公开样本；不绕过他人产品的技术保护措施。

代表工具：Ghidra · IDA Pro · Frida

09

漏洞挖掘 / FuzzingVulnerability Research

漏洞挖掘把「可能有问题」变成「可复现的影响」，模糊测试与代码审计是两条主线。

  • 攻击面建模：先列出输入面与信任边界，再决定测哪里。
  • 模糊测试：覆盖率引导的 Fuzzer 配合消毒器（ASan / UBSan）是发现内存问题的高效组合。
  • 代码审计：数据流与污点分析优先于模式匹配，静态与动态互相验证。
  • 复现与定级：稳定复现、影响评估与 CVSS 打分；区分「可利用」与「仅崩溃」。
  • 披露：遵循厂商响应与协调披露窗口，不公开未修复细节。

代表工具：Slither · AFL++ · libFuzzer

10

云原生与容器安全Cloud Native

云原生安全的关键是「配置即攻击面」：镜像、集群、IAM 与运行时四层都要看。

  • 镜像与依赖：最小基础镜像、非 root 运行、签名与 SBOM；构建期扫描。
  • 集群配置：CIS Benchmark、RBAC 最小化、NetworkPolicy 与准入控制。
  • 云 IAM：避免长期密钥，权限边界与跨账号信任要定期复核。
  • 运行时：系统调用与容器行为检测；异常进程与逃逸尝试优先告警。
  • 供应链：镜像来源、CI 凭据与制品仓库权限同属云上攻击面。

代表工具：kube-bench · kube-hunter · Falco

11

移动安全Mobile Security

移动安全分两端：客户端的数据与通信，以及服务端为移动端开放的接口。

  • 静态分析：清单、权限、硬编码密钥与第三方 SDK；先看导出组件。
  • 动态分析：Hook 关键 API、抓包与证书固定验证（仅限自有或授权 App）。
  • 存储与通信：Keychain / Keystore 使用是否正确，传输是否真正校验证书。
  • 加固与检测：混淆、完整性校验与反调试只提高成本，不能替代服务端校验。
  • 平台差异：iOS 与 Android 的沙箱、权限模型与分发渠道各不相同。

代表工具：MobSF · jadx

12

嵌入式 / IoT / 工控Embedded & ICS

嵌入式与工控的约束是资源、寿命与物理可达性；默认口令与不升级是长期主因。

  • 固件：提取文件系统、找硬编码凭据与调试接口；确认签名与安全启动是否启用。
  • 协议：Modbus、MQTT、BLE 等协议的真实认证与加密能力常被高估。
  • 网络暴露：设备放进独立网段并限制出站；不要把工控协议直接暴露到互联网。
  • 生命周期：补丁与密钥轮换在十年生命周期内如何执行，要在采购时回答。
  • 物理与供应链：调试口、串口与替换固件是常见入口。

代表工具：binwalk · EMBA

13

数据安全与隐私Data Security & Privacy

数据安全的目标是「知道有什么、谁能用、用完能否删」，技术手段服务于这个流程。

  • 分类分级：先定义敏感级别，再谈加密与脱敏，否则策略无法落地。
  • 最小化与目的限定：收集前回答「为什么需要」，比事后脱敏更有效。
  • 脱敏与令牌化：测试与共享环境使用不可逆或可映射的替代值。
  • 访问与审计：行级 / 列级权限、动态脱敏与查询审计三者配合。
  • 生命周期：保留期限、导出审批与删除验证要有可核查记录。

代表工具：Presidio

14

应急响应与取证Incident Response & Forensics

应急响应的价值在「多快能定性、多快能止损」，取证的价值在「证据能否被采信」。

  • 准备：预案、联系人、隔离手段与日志保留期先于事件发生。
  • 定性与范围：从告警到时间线；先确认影响面，再决定是否断网。
  • 取证：内存与磁盘镜像按顺序采集，记录哈希与监管链。
  • 根除与恢复：清除持久化、轮换凭据，再谈恢复业务。
  • 复盘：把检测缺口写回规则与架构，而不是只写一份报告。

代表工具：Volatility · Velociraptor

15

威胁情报与漏洞管理Threat Intelligence

情报的价值在于「可执行」：能不能落到封禁、检测规则与补丁优先级上。

  • 情报分级：战略、战术、运营与技术情报用途不同，不要混用。
  • 共享格式：STIX / TAXII、MISP 等格式让情报可交换、可自动化。
  • 漏洞管理：以资产暴露面与可达性排序，而不是只看 CVSS。
  • 检测落地：IOC 会过期，行为与 TTP 的检测更耐久。
  • 合规边界：情报共享注意隐私与来源保护。

代表工具：MISP · OpenVAS

16

审计与合规Audit & Compliance

审计日志要能回答「谁在什么时候对什么做了什么」，合规则是把这件事制度化。

  • 审计日志只追加、不可篡改，并与业务日志分开存储。
  • 记录身份、时间、来源、对象、动作与结果，避免记录敏感明文。
  • 等保 2.0 关注身份鉴别、访问控制、安全审计与入侵防范等控制项。
  • GDPR / 个人信息保护法要求最小收集、目的限定、可删除与可导出。
  • 保留期限、访问审批与审计复核要有明确责任人。
