开发
场景

先选开发场景，再看架构模式，最后落到语言与框架。场景不是语言分类，而是「你要做什么」；同一个框架可以出现在多个场景里，但取舍不同。每个场景的架构分组都归入 12 种统一模式，便于跨场景比较。

12 种统一架构模式 · 场景保留各自焦点，模式用于跨场景比较

01 分层 / MVC请求 → 控制器 → 服务 → 数据层；约定清晰，适合大多数业务系统。02 微服务 / 服务化按业务边界拆服务或模块，独立部署与团队自治优先，代价是运维与一致性。03 事件驱动 / Actor通过消息与事件解耦，或用 Actor 封装状态；适合实时、长流程与高并发。04 组件化 / 响应式 UI以组件树组织界面，状态与副作用显式管理；声明式 UI 也归入这一类。05 同构渲染 / SSR服务端渲染首屏，客户端接管交互；内容站与 SEO 敏感场景优先。06 网关 / BFF统一入口、协议转换与接口聚合；让客户端只面对一个边界。07 原生 / 平台绑定直接使用平台 API、控件或系统库；兼容性与系统能力最完整。08 跨平台 / Web 外壳一套代码覆盖多平台，或以内嵌 Web 运行时承载界面；复用优先。09 微内核 / 插件化核心保持小，能力通过插件或脚本扩展；适合编辑器、IDE 与平台型工具。10 ECS / 数据导向按组件与系统组织数据，缓存友好；适合大量实体、数组式计算与数据并行。11 管线 / 批流分阶段转换与批流处理，强调可重跑、可测试与可观测。12 控制面 / 编排声明期望状态，由控制器收敛；适合基础设施、部署与升级流程。

后端开发

先确定团队规模、交付节奏与集成边界，再在分层、微服务与事件驱动之间选择。
