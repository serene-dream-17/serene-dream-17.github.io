02

适用与规避Tradeoffs

适用

  • 渐进增强的既有站点
  • 中小团队与外包交付
  • 需要低上手成本

不适用

  • 需要极大规模跨团队协作
  • 依赖特定 React 生态库
03

落地结构Layout

目录结构是示意，不是强制约定；按团队与构建工具调整。

  • src/views 页面
  • src/components 组件
  • src/stores 状态
  • src/router 路由

04

替代栈Alternatives

Web 前端技术栈React 单页应用浏览器端渲染的组件化应用，后端只提供 API；生态最成熟，适合交互密集的产品界面。Web 前端技术栈Next.js 全栈 Web用一套 TypeScript 代码覆盖首屏渲染、API 与静态生成，适合内容与产品混合的站点。
05

工程化深度Engineering

版本是策展建议线（LTS 或当前稳定线）；链路、容量与 SLO 为示意口径，具体数值需按实测与官方文档校准。

版本基线Baseline

  • Vue 3.5 稳定线
  • Vite 6
  • TypeScript 5.x
  • Pinia 2

测试与 CITesting

  • 单元：Vitest
  • 端到端：Playwright
  • CI：类型检查 + 单测 + 构建

部署与运维Operations

  • 构建：静态资源
  • 部署：CDN / 静态托管
  • 监控：错误上报 + 性能采样

团队与成本Team

  • 1–4 人
  • JS/TS + 模板语法
  • 成本：低

数据与请求链路Flow

  • 加载：Vite 产物 → CDN → Vue Router
  • 数据：组件 → API → 服务端
  • 状态：Pinia 管理跨页状态与缓存

性能与容量Capacity

  • 首屏：路由级懒加载
  • 瓶颈：深层响应式与大列表
  • 扩容：静态资源 CDN

可观测性与 SLOObservability

  • 指标：Web Vitals、组件错误
  • 日志：错误上报带构建版本
  • 告警：错误率与接口超时

安全与合规Security

  • 认证：短时令牌 + 刷新机制
  • 模板：默认转义，慎用 v-html
  • 依赖：审计与版本锁定

技术栈为策展组合；组件版本、许可与默认配置以官方文档为准。
