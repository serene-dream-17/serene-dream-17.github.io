Web 前端

5 个栈 组件化与渲染策略优先，先定首屏与交互模型。
Web 前端技术栈 Next.js 全栈 Web 用一套 TypeScript 代码覆盖首屏渲染、API 与静态生成，适合内容与产品混合的站点。 TypeScript · Next.js Web 前端技术栈 React 单页应用 浏览器端渲染的组件化应用，后端只提供 API；生态最成熟，适合交互密集的产品界面。 TypeScript · React Web 前端技术栈 Vue 渐进式应用 模板语法直观、可以按需引入；适合由服务端渲染页面逐步增强为单页应用的项目。 Vue · TypeScript Web 前端技术栈 Angular 企业前端 TypeScript 全家桶：依赖注入、路由与表单约定齐全，适合多人长期维护的企业前端。 TypeScript · Angular Web 前端技术栈 Blazor 全栈 用 C# 写前端与服务端共享模型，适合已有 .NET 团队与内部系统。 C# · Blazor · ASP.NET Core

Web 后端

7 个栈 按团队规模与数据一致性要求选择全栈或服务化。
Web 后端技术栈 Django 全栈 约定齐全的 Python 全栈方案：ORM、后台、认证与迁移开箱即用，适合快速交付业务系统。 Python · Django Web 后端技术栈 Spring Boot 企业后端 Java / Kotlin 的企业级默认解：依赖注入、事务、安全与可观测性都有成熟方案。 Java · Kotlin · Spring Boot Web 后端技术栈 ASP.NET Core 后端 C# 的跨平台企业栈，语言特性与工具链统一，适合已有 .NET 团队与 Windows 生态。 C# · ASP.NET Core Web 后端技术栈 Rails 快速交付 约定优于配置的全栈框架，生成器与迁移齐备；适合验证期产品与内部系统。 Ruby · Rails Web 后端技术栈 NestJS BFF 为多端前端提供聚合与契约层的 Node 服务，模块化与依赖注入接近企业后端习惯。 TypeScript · NestJS Web 后端技术栈 Laravel 全栈 PHP 生态里约定完整的一套：路由、ORM、队列与模板齐全，部署门槛低。 PHP · Laravel Web 后端技术栈 Sinatra API 极简 Ruby 路由框架，适合小接口、Webhook 与内部工具服务。 Ruby · Sinatra

服务化 / 云原生

8 个栈 独立部署、弹性与可观测性优先，代价是运维复杂度。
服务化 / 云原生技术栈 Go 微服务 静态二进制、低内存与简单部署，适合按业务边界拆分的服务群。 Go · Gin · gRPC-Go 服务化 / 云原生技术栈 Quarkus 原生化 为 JVM 生态补上快速启动与低内存：编译期处理加 GraalVM 原生镜像，适合 Serverless 与弹性扩缩。 Java · Quarkus 服务化 / 云原生技术栈 Phoenix 实时应用 Elixir 与 BEAM 的软实时优势：长连接、频道与热升级，适合协作与实时 UI。 Elixir · Phoenix · LiveView 服务化 / 云原生技术栈 Akka 集群 以 Actor 模型表达并发与分布式的 JVM 方案，适合有状态、长流程的服务。 Scala · Java · Akka 服务化 / 云原生技术栈 Rust 服务端 类型安全与可预测的延迟：适合网关、代理与高吞吐服务，代价是开发速度与生态成熟度。 Rust · Axum 服务化 / 云原生技术栈 Kubernetes 控制面 用声明式 API 与控制器收敛期望状态；适合平台工程与自研 Operator。 Go · controller-runtime · Kubernetes 服务化 / 云原生技术栈 Play 全栈 Scala 的异步 Web 框架，适合需要类型安全与高并发的服务端。 Scala · Play · Akka 服务化 / 云原生技术栈 Cowboy 网关 Erlang/OTP 上的 HTTP 与 WebSocket 服务，适合长连接与高可用网关。 Erlang · Cowboy · OTP

移动

3 个栈 平台优先级决定原生还是跨端，离线与推送要提前设计。
移动技术栈 Flutter 跨端 一套 Dart 代码覆盖 iOS、Android 与桌面；自绘渲染带来一致性，也带来包体与原生集成的取舍。 Dart · Flutter 移动技术栈 iOS 原生 SwiftUI 与 UIKit 直接使用 Apple 平台能力，系统集成与体验最完整。 Swift · SwiftUI · UIKit 移动技术栈 Android 原生 Kotlin 与 Jetpack Compose 的官方路线，系统能力、后台限制与分发策略都按平台规则走。 Kotlin · Jetpack Compose · Android SDK

桌面

3 个栈 系统集成深度与分发方式决定原生、跨平台或 Web 外壳。
桌面技术栈 Qt 桌面 成熟的跨平台原生控件与工具链，适合需要系统集成、长生命周期的桌面软件。 C++ · Qt 桌面技术栈 Tauri 桌面 Web 前端加 Rust 后端的小体积桌面外壳，复用前端技能并保留系统调用能力。 Rust · TypeScript · Tauri 桌面技术栈 WPF 企业桌面 Windows 原生桌面与数据绑定成熟，适合企业内部工具与长期维护的客户端。 C# · WPF

数据技术栈 dbt 数仓转换 以 SQL 为中心做数仓建模与测试，版本化、可重跑，适合分析工程团队。 SQL · dbt 数据技术栈 Spark 批处理 Scala / Python 的大规模批处理与 SQL 引擎，适合 PB 级离线计算与特征加工。 Scala · Python · Apache Spark 数据技术栈 R Shiny 数据应用 用 R 直接把分析变成可交互应用，适合统计团队与内部数据产品。 R · Shiny · tidyverse
