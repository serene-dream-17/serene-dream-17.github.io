01

语言档案Dossier

Common Lisp 不是某个人设计的，而是 1980 年代初各家 Lisp 实现（Maclisp、Franz Lisp、Interlisp 等）的合并产物。1984 年的《Common Lisp the Language》定义了第一版标准，1994 年由 ANSI 正式标准化。

它把 Lisp 的能力系统化了：包（package）管理名字，CLOS 提供泛型函数与多重方法，条件系统（condition system）把错误处理与恢复分开，宏在编译期改写代码。

与早期的 LISP 相比，Common Lisp 的产物链更工程化：compile-file 生成实现相关的 FASL，ASDF 管理系统依赖，save-lisp-and-die 可以把运行时与程序一起保存成独立可执行文件。

01 hello.lisp 源码 $ cat hello.lisp
hello.lisp 示意样例 
(defpackage :hello
  (:use :cl)
  (:export :main))

(in-package :hello)

(defclass greeter ()
  ((name :initarg :name :reader name)))

(defmethod greet ((g greeter))
  (format t "Hello, ~a!~%" (name g)))

(defun main ()
  (greet (make-instance 'greeter :name "world")))
文档重构 · 非实测输出
包defpackage 管理符号归属
类defclass + 槽 + reader
方法defmethod 按参数特化
入口main 是自己约定的函数

Common Lisp 没有标准的主函数。main 只是约定，真正启动要靠实现提供的保存/导出机制。

Common Lisp 的宏不是文本替换：它接收已读取的表达式，返回新表达式，然后继续编译。

03 hello.fasl FASL $ sbcl --eval '(compile-file "hello.lisp")'
hello.fasl 示意样例

; FASL 结构（实现相关，示意）
;   header  : 魔数 / 版本 / 字长 / 特性
;   code    : 编译后的函数对象
;   data    : 字面量、符号、调试信息
;   linking : 加载时重定位

$ ls -lh hello.fasl

文档重构 · 非实测输出
FASLFast Load，编译产物
绑定与实现、版本、字长相关
内容代码 + 字面量 + 符号 + 调试信息
加载跳过读取与宏展开

FASL 是「可加载的代码块」，不是可执行文件。它必须由同一实现的运行时加载。

04 hello 独立可执行 $ sbcl --load hello.lisp --eval '(sb-ext:save-lisp-and-die "hello" :executable t :toplevel (quote hello:main))'
hello 示意样例 
$ ./hello
Hello, world!

$ file hello
hello: ELF 64-bit LSB executable, x86-64 ...

$ ls -lh hello

; 可执行文件 = Lisp 运行时 + 镜像
; 启动即恢复堆，不重新初始化
文档重构 · 非实测输出
机制保存镜像并加上可执行头
体积通常 40–60 MB
启动恢复堆，然后调用 toplevel
平台与保存时的 OS/架构绑定

Common Lisp 的独立程序本质上是一个带着 Lisp 世界的可执行镜像。启动快，但体积大、平台绑定强。

  1. 包：解决大型程序中符号重名，是模块系统的 Lisp 版本。
  2. CLOS：泛型函数与多重方法，把 OO 从「类的成员」变成「方法的组合」。
