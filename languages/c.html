01

语言档案Dossier

1972 年，Dennis Ritchie 在贝尔实验室把 B 改造成 C：加入类型、结构体、字节寻址和可移植的编译模型。最初的理由很具体——B 只有一种字类型，无法在 PDP-11 上高效地按字节操作。

C 的产物链是现代工具链的原型：预处理、编译、汇编、链接，每一步都有明确的输入输出。.c → .i → .s → .o → ELF 这条链不仅属于 C，也属于 C++、Rust、Go、Swift 等后来者。

C 的另一个决定是「不规定运行时」。没有 GC、没有异常、没有标准输出函数——这些都在库或操作系统里。正因如此，C 能贴近硬件，也把大量责任交给了程序员。

产物链Artifact Chain

01 hello.c 源码 $ cat hello.c
hello.c 示意样例 
#include <stdio.h>

int main(void) {
    printf("Hello, world\n");
    return 0;
}
文档重构 · 示意输出
编码UTF-8 / ASCII，文本
预处理以 # 开头的行交给 cpp
翻译单元一个 .c + 它包含的头文件
入口main，由 C 运行时调用

C 的「源文件」并不是编译器真正看到的东西。编译器看到的是预处理之后的翻译单元。

文档重构 · 示意输出

一个 5 行的程序，预处理后可能有两万行，绝大多数来自 stdio.h。# 1 "hello.c" 这样的行标记让编译器在报错与调试时仍能指回原始文件。

03 hello.s 汇编 $ gcc -S -O0 hello.c -o hello.s
hello.s 示意样例 
    .file   "hello.c"
    .text
    .section    .rodata
.LC0:
    .string "Hello, world"
    .text
    .globl  main
    .type   main, @function
main:
.LFB0:
    .cfi_startproc
    endbr64
    pushq   %rbp
    .cfi_def_cfa_offset 16
    .cfi_offset 6, -16
    movq    %rsp, %rbp
    .cfi_def_cfa_register 6
    leaq    .LC0(%rip), %rdi
    movl    $0, %eax
    call    printf@PLT
    movl    $0, %eax
    popq    %rbp
    .cfi_def_cfa 7, 8
    ret
    .cfi_endproc
文档重构 · 示意输出
语法GNU as（AT&T：源在左，目标在右）
段.text 代码 · .rodata 只读数据
调用printf@PLT，经过程序链接表
CFI调用帧信息，供调试与异常回溯

同一个 hello.c，GCC 常把 printf 优化成 puts；这里保留 printf 是为了展示 PLT 调用。-O2 会移除栈帧，代码只剩几条指令。

05 hello 可执行 $ gcc -o hello hello.c && file hello
hello 示意样例 
$ file hello

       interpreter /lib64/ld-linux-x86-64.so.2

$ readelf -h hello | grep -E 'Type|Entry'
  Type:    DYN (Position-Independent Executable)
  Entry:   0x1050

$ readelf -l hello | grep -A1 INTERP

Hello, world
文档重构 · 示意输出
类型ET_DYN（PIE，位置无关可执行）
解释器/lib64/ld-linux-x86-64.so.2
依赖libc.so.6

入口0x1050，先跑 _start 再调 main

可执行文件并不直接调用 printf。它调用 PLT 桩，桩再通过 GOT 跳到 libc 里的真实地址；首次调用还会触发动态链接器解析符号。

体积与形态 · 对数尺度示意

hello.c78 B
hello.i≈ 18 KB
hello.s≈ 1.3 KB
hello.o≈ 1.5 KB
hello≈ 16 KB
+ libc≈ 2 MB
  1. 预处理：把宏、条件编译、头文件展开成编译器能直接处理的一个翻译单元。
  2. 汇编：把与机器无关的 C 降到具体指令集，保留符号与段信息。
  3. 目标文件：允许分别编译；未解析的符号留给链接器。
  4. 链接：把多个 .o 与库合并，解析 printf，生成可加载的段表。
  5. 动态链接：printf 的代码不在 hello 里，而在 libc.so；运行时由 ld.so 绑定。
